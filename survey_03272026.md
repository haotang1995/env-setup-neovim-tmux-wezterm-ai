# Survey: AI CLI Agent Chat History Storage

**Date:** 2026-03-27
**Agents surveyed:** Claude Code, Codex CLI, Copilot CLI

---

## 1. Methodology

### Step 1: Initial exploration (filesystem)

Before looking at source code, we explored the actual files on disk to
understand what each agent stores locally.

**Claude Code:**
- Listed `~/.claude/` directory structure (9.0 MB total)
- Found `history.jsonl`, `sessions/`, `projects/`, `file-history/`,
  `shell-snapshots/`, `backups/`, `cache/`, `plans/`, `plugins/`
- Read sample lines from `history.jsonl` (28 entries, ~11 KB)
- Read session JSONL files from `projects/` — found full conversation content
- Read session metadata from `sessions/<pid>.json`
- Read file-history versioned snapshots

**Codex CLI:**
- Listed `~/.codex/` directory (636 KB)
- Found `auth.json`, `log/`, `memories/`, `config.toml`
- No session files present (no Codex conversations had been run on this machine)
- Noted the documented path `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`

**Copilot CLI:**
- Listed `~/.copilot/` directory (680 KB)
- Found `config.json`, `command-history-state.json`, `session-state/`, `logs/`
- Read `workspace.yaml` files — metadata only (no conversation content)
- Read `checkpoints/index.md` — empty Markdown table template
- Read log files — structured JSON telemetry, no conversation content
- Observed `conversation_tokens: 0`, `turn_count: 0` in telemetry
- Observed `memory_retrieval` events confirming server-side context fetch
- **Conclusion: conversations are server-side only**

## 2. Findings Summary

### 2.1 Claude Code

**Storage:** Local JSONL files per session, per project.

**Directory layout:**
```
~/.claude/
├── history.jsonl                              # Global index (lightweight)
├── sessions/<pid>.json                        # Session metadata
├── projects/<encoded-project>/
│   ├── <sessionId>.jsonl                      # Full conversation
│   └── <sessionId>/subagents/
│       └── agent-<agentId>.jsonl              # Subagent conversations
├── file-history/<sessionId>/
│   └── <fileHash>@v<n>                        # Versioned file snapshots
└── shell-snapshots/
    └── snapshot-<shell>-<ts>-<random>.sh
```

**Encoded project path:** absolute path with `/` replaced by `-`
(e.g. `/home/tanghao/myproject` → `-home-tanghao-myproject`)

#### Global index (`history.jsonl`)

| Field | Type | Description |
|-------|------|-------------|
| `display` | string | User-facing summary of the interaction |
| `pastedContents` | object | Pasted content blocks keyed by ID |
| `timestamp` | number | Unix milliseconds |
| `project` | string | Absolute project path |
| `sessionId` | string | UUID |

Example:
```json
{"display":"I would like to set up a docker...","pastedContents":{},"timestamp":1774369493465,"project":"/home/tanghao/env-setup-neovim-tmux-wezterm-ai","sessionId":"5de32441-be88-406c-9208-fd0af3351900"}
```

#### Session metadata (`sessions/<pid>.json`)

| Field | Type | Description |
|-------|------|-------------|
| `pid` | number | Process ID |
| `sessionId` | string | UUID |
| `cwd` | string | Working directory |
| `startedAt` | number | Unix ms |
| `kind` | string | `"interactive"` or `"batch"` |

#### Conversation JSONL line types

Common envelope fields on every line:
`uuid`, `timestamp` (ISO-8601), `sessionId`, `parentUuid`, `isSidechain`,
`userType`, `entrypoint`, `cwd`, `version`, `gitBranch`, `slug`

**`type: "user"` — User message:**
```json
{
  "parentUuid": null,
  "isSidechain": false,
  "promptId": "dc5690b0-...",
  "type": "user",
  "message": {
    "role": "user",
    "content": "I would like to set up a docker environment..."
  },
  "uuid": "c255128e-...",
  "timestamp": "2026-03-24T16:24:53.595Z",
  "permissionMode": "default",
  "userType": "external",
  "entrypoint": "cli",
  "cwd": "/home/tanghao/env-setup-neovim-tmux-wezterm-ai",
  "sessionId": "5de32441-...",
  "version": "2.1.81",
  "gitBranch": "main"
}
```

`message.content` can also be an array containing tool results:
```json
"content": [
  {"tool_use_id": "toolu_014PPe...", "type": "tool_result", "content": "#!/usr/bin/env bash\n..."}
]
```

**`type: "assistant"` — Claude response:**
```json
{
  "parentUuid": "840925aa-...",
  "isSidechain": false,
  "message": {
    "model": "claude-opus-4-6",
    "id": "msg_01MAPBJ4...",
    "type": "message",
    "role": "assistant",
    "content": [
      {"type": "text", "text": "Yes, I understand..."},
      {"type": "tool_use", "id": "toolu_017Yj4...", "name": "Agent", "input": {...}, "caller": {"type": "direct"}},
      {"type": "thinking", "thinking": "Let me analyze...", "signature": "base64..."}
    ],
    "stop_reason": "end_turn",
    "stop_sequence": null,
    "usage": {
      "input_tokens": 3,
      "cache_creation_input_tokens": 22381,
      "cache_read_input_tokens": 8693,
      "output_tokens": 428,
      "service_tier": "standard",
      "cache_creation": {"ephemeral_1h_input_tokens": 22381, "ephemeral_5m_input_tokens": 0}
    }
  },
  "requestId": "req_011CZN...",
  "type": "assistant",
  "uuid": "1555a8ab-...",
  "timestamp": "2026-03-24T16:25:05.840Z",
  ...envelope fields...
}
```

**`type: "progress"` — Subagent/hook progress:**
```json
{
  "type": "progress",
  "data": {
    "type": "agent_progress",
    "agentId": "afd4f1184b9d18ea6",
    "prompt": "Search the web for...",
    "message": {"type": "user", "message": {"role": "user", "content": [...]}}
  },
  "toolUseID": "agent_msg_01Pmk...",
  "parentToolUseID": "toolu_017Yj4...",
  ...envelope fields...
}
```

**`type: "system"` — Turn duration / meta events:**
```json
{
  "type": "system",
  "subtype": "turn_duration",
  "durationMs": 132979,
  "isMeta": false,
  ...envelope fields...
}
```

**Other types:** `"file-history-snapshot"`, `"last-prompt"`, `"queue-operation"` —
metadata/housekeeping, not conversation content.

#### Subagent storage

```
<sessionId>/subagents/
├── agent-<agentId>.jsonl       # Same JSONL format, isSidechain: true
└── agent-<agentId>.meta.json   # {"agentType":"Explore","description":"..."}
```

- Subagent files contain **only their own turns**
- Parent references subagents via `progress` events with `agentId`
- Single-level nesting only (no sub-subagents)
- All share the parent's `sessionId`

### 2.2 Codex CLI

**Storage:** Local JSONL files per session, organized by date.

**Directory layout:**
```
~/.codex/
├── history.jsonl                              # Global index
├── sessions/YYYY/MM/DD/
│   └── rollout-YYYY-MM-DDThh-mm-ss-<uuid>.jsonl
├── archived_sessions/
└── state.db                                   # SQLite (thread metadata)
```

#### Global index (`history.jsonl`)

| Field | Type | Description |
|-------|------|-------------|
| `session_id` | string | UUID |
| `ts` | number | Unix seconds |
| `text` | string | User message text |

Truncation: configurable `history.max_bytes`, soft cap at 80% (`HISTORY_SOFT_CAP_RATIO`).

#### Rollout JSONL format

Each line is a `RolloutLine`:
```json
{"timestamp": "2025-05-07T17:24:21.123Z", "type": "<variant>", "payload": {...}}
```

Serde: `#[serde(tag = "type", content = "payload", rename_all = "snake_case")]`

**`RolloutItem` variants:**

| `type` | Payload struct | Description |
|--------|----------------|-------------|
| `"session_meta"` | `SessionMetaLine` | Session identity (first line) |
| `"response_item"` | `ResponseItem` | Messages, reasoning, tool calls |
| `"compacted"` | `CompactedItem` | Context compaction |
| `"turn_context"` | `TurnContextItem` | Per-turn metadata |
| `"event_msg"` | `EventMsg` | Lifecycle events |

**`SessionMeta` fields:**

| Field | Type | Description |
|-------|------|-------------|
| `id` | ThreadId | Session UUID |
| `forked_from_id` | Option<ThreadId> | Parent session if forked |
| `timestamp` | string | RFC3339 |
| `cwd` | PathBuf | Working directory |
| `originator` | string | `"codex"` |
| `cli_version` | string | Version |
| `source` | SessionSource | `Cli`, `VSCode`, etc. |
| `agent_nickname` | Option<string> | Agent name |
| `agent_role` | Option<string> | Agent role |
| `model_provider` | Option<string> | e.g. `"anthropic"` |
| `memory_mode` | Option<string> | e.g. `"disabled"` |
| `git` | Option<GitInfo> | Branch, commit info |

**`ResponseItem` variants** (from `models.rs`):
- `Message{id, role, content: [ContentItem], end_turn, phase}`
  - `ContentItem`: `InputText{text}`, `OutputText{text}`, `InputImage{image_url}`
- `Reasoning{id, summary, content}`
- `FunctionCall{name, arguments (JSON string), call_id, namespace}`
- `FunctionCallOutput{call_id, output}`
- `LocalShellCall{call_id, status, action}`
- `CustomToolCall`, `CustomToolCallOutput`
- `WebSearchCall`, `ImageGenerationCall`
- Others: `McpListResource`, `McpReadResource`, `GhostSnapshot`, etc.

**`EventMsg` variants** (30+ types, key ones):
- `UserMessage{message, images, text_elements}`
- `AgentMessage{message, phase}`
- `AgentReasoning{content}`
- `TurnStarted{turn_id}` (alias: `task_started`)
- `TurnComplete{turn_id, last_agent_message}` (alias: `task_complete`)
- `ExecCommandBegin/End` — shell command lifecycle
- `McpToolCallBegin/End` — MCP tool lifecycle
- `TokenCount{info: {total_token_usage, last_token_usage}}`
- `Error`, `Warning`

**Persistence modes:**
- `Limited`: messages, reasoning, tool calls, turn lifecycle
- `Extended`: adds command output, patch results, MCP results

**Key source files:**
- `codex-rs/protocol/src/protocol.rs` — RolloutLine, RolloutItem, SessionMeta, EventMsg
- `codex-rs/protocol/src/models.rs` — ResponseItem, ContentItem
- `codex-rs/rollout/src/recorder.rs` — write/load logic
- `codex-rs/core/src/message_history.rs` — global history
- `codex-rs/rollout/src/policy.rs` — persistence policy

#### Fork/subagent handling

- Each forked session gets its own rollout file in the same `YYYY/MM/DD/` directory
- Child's `SessionMeta` has `forked_from_id: <parent-uuid>`
- Child file contains **full copy of parent history** + child's own items
- Parent-child edges tracked in SQLite (`thread_spawn_edges` table)
- Spawning: `spawn_agent_with_metadata()` in `codex-rs/core/src/agent/control.rs`
- Multi-level nesting supported via `forked_from_id` chains

### 2.3 Copilot CLI

**Storage:** Conversations stored **server-side only**.

**Local directory layout:**
```
~/.copilot/
├── config.json                    # Auth tokens (gho_*) + settings
├── command-history-state.json     # CLI command names only: {"commandHistory":["/login"]}
├── session-state/<uuid>/
│   ├── workspace.yaml             # Session metadata (no messages)
│   ├── checkpoints/index.md       # Empty checkpoint table
│   ├── files/                     # Empty
│   └── research/                  # Empty
├── logs/process-<ts>-<pid>.log    # JSON telemetry only
├── ide/                           # Empty (IDE integration)
├── skills/                        # Symlinks to shared skill library
└── lsp-config.json                # LSP server configuration
```

**`workspace.yaml` fields:**
| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Session UUID |
| `cwd` | string | Working directory |
| `summary_count` | number | Always 0 locally |
| `created_at` | string | ISO-8601 |
| `updated_at` | string | ISO-8601 |
| `git_root` | string | Repo root |
| `repository` | string | `owner/repo` |
| `host_type` | string | `"github"` |
| `branch` | string | Git branch |

**What's NOT stored locally:**
- User messages
- AI responses
- Tool call inputs/outputs
- Conversation context

**Evidence for server-side storage:**
- Log telemetry shows `conversation_tokens: 0`, `turn_count: 0`
- `memory_retrieval` events confirm context fetched from remote APIs
- Feature flag `copilot-feature-agentic-memory` suggests server-side memory system
- `--resume` flag works by referencing server-side session state

## 3. Overall Comparison

| Feature | Claude Code | Codex CLI | Copilot CLI |
|---------|-------------|-----------|-------------|
| **Local chat storage** | Yes (JSONL) | Yes (JSONL) | No (server-side) |
| **Format** | JSONL per session | JSONL per session | N/A |
| **Organization** | By project + session UUID | By date (YYYY/MM/DD) | N/A |
| **Global index** | `history.jsonl` (display + metadata) | `history.jsonl` (session_id + text) | `command-history-state.json` (commands only) |
| **Subagent/fork** | Separate JSONL per subagent in subdirectory | Separate rollout file + SQLite edges | N/A |
| **Parent history in child** | No (child has own turns only) | Yes (full copy) | N/A |
| **File versioning** | `file-history/<session>/<hash>@v<n>` | No | No |
| **Compaction** | No | Yes (`CompactedItem`) | N/A |
| **Resume** | By sessionId | By threadId or file path | Via `--resume` (server-side) |
| **Source available** | No (closed-source CLI) | Yes (Rust) | No (closed-source CLI) |
| **Nesting depth** | Single level only | Multi-level via `forked_from_id` | N/A |
